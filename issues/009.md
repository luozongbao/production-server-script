# Issue #009 — Customizable colored PS1 prompt via .env

**Severity**: feature
**Status**: open
**Target**: v1.1.0
**File**: [setup.sh](../../setup.sh) — new section

## ⚠️ Flags conflict with v1.0

`--install-defaults` currently uses the short flag **`-p`**. This issue needs `-p` for `--prompt`.

**Resolution:** rename the existing `install-defaults` flag in the same v1.1.0 release:

| Old (v1.0) | New (v1.1.0) |
|---|---|
| `--install-defaults` | `--install-packages` |
| `-p` | `-i` |

This is a **breaking change** — must be called out in CHANGELOG and RELEASE notes.

## Problem

The script currently does not customize the shell prompt. After login, the user sees the distro default PS1, which is usually plain and unhelpful:

```
root@web-prod-01:/etc/nginx#
```

Admins working on multiple servers benefit from a PS1 that:
- Shows the **username** (`root` vs ordinary user)
- Shows the **hostname** in color
- Highlights the **working directory**
- Visually flags **root** sessions (red) vs normal user (green)
- Optionally shows **date/time** and **git branch** for context

But PS1 is highly personal — every admin has their own preference. Hardcoding one in the script would force every user to edit it manually.

## Proposed design

Add a new section `section_bashrc` that, when enabled, appends a guarded PS1 block to `~/.bashrc` for `TARGET_USER`. The PS1 template itself is **driven by `.env`**, with a sensible default baked into the script.

### `.env` variables

```bash
# Set to "true" to install the managed PS1 block into TARGET_USER's .bashrc.
PROMPT_ENABLED=true

# PS1 template. Use ANSI escape codes (\\[ \\] around them).
# Leave blank to use the built-in default.
PROMPT_PS1_TEMPLATE=
```

### Default PS1 (used when `PROMPT_PS1_TEMPLATE` is blank)

The user-supplied template had two issues:

1. **Brand-new git repos (no commits yet) break `git branch`** — it returns empty output (and `2>/dev/null` hides the underlying error). The prompt then silently shows nothing where the branch should be.
2. **Three separate `\D{...}` calls** each fork `date(1)` on every prompt redraw — wasteful on slow VMs.

**Fixed default PS1:**

```bash
PS1='\[\033[1;90m\]\D{%y-%m-%d %H:%M}\[\033[0m\] \[\033[1;32m\]\u@\h\[\033[0m\]:\[\033[1;34m\]\w\[\033[0;33m\]$(git symbolic-ref --short HEAD 2>/dev/null | sed "s/^/ (/" && echo ")")\[\033[0m\]\$ '
```

Changes from the original:
- `\D{%y%m%d}\D{%H}\D{%m}` → single `\D{%y-%m-%d %H:%M}` (1 fork instead of 3)
- `git branch | sed ...` → `git symbolic-ref --short HEAD` (works on repos with zero commits, returns `main` even before first commit)

Renders as:

```
26-09-24 19:09 web@host:~/projects/production-server-script (dev)$
```

Components (left to right):
- Gray date+time stamp
- Green user@host
- Blue working directory
- Yellow git branch in parens (works even on fresh repos)
- `$` (or `#` if root) at the end

### Snippet appended to `~/.bashrc` (idempotent, guarded)

```bash
# >>> production-server-script:PROMPT >>>
if [[ -z "${PROMPT_OVERRIDE:-}" ]]; then
  export PROMPT_OVERRIDE=1
  export PS1='<resolved PS1 here — either .env value or default>'
fi
# <<< production-server-script:PROMPT <<<
```

The guard:
- `[[ -z "${PROMPT_OVERRIDE:-}" ]]` — only sets once per shell
- The `>>>` / `<<<` markers — `setup.sh` detects existing block on re-run and replaces it in place (idempotent, no duplication)

### How re-run behavior works

```
1. Detect existing block by grepping for `>>> production-server-script:PROMPT >>>`
2. If found:   sed-replace the OLD block contents with NEW block contents
3. If missing: append the block at the end of .bashrc
```

This means **editing `PROMPT_PS1_TEMPLATE` and re-running `setup.sh`** updates the prompt without manual editing.

### Performance note

Even with the fix above, `git symbolic-ref` still forks on every prompt redraw. On large git repos, recommend replacing with a cached helper:

```bash
# Cached git branch (refresh every 5s)
__git_ps1() {
  local now=$(date +%s) last=${_PROMPT_GIT_LAST:-0}
  (( now - last < 5 )) && { [[ -n "${_PROMPT_GIT_BRANCH:-}" ]] && printf ' (%s)' "$_PROMPT_GIT_BRANCH"; return; }
  local b; b=$(git symbolic-ref --short HEAD 2>/dev/null)
  _PROMPT_GIT_BRANCH="$b"; _PROMPT_GIT_LAST=$now
  [[ -n "$b" ]] && printf ' (%s)' "$b"
}
```

Documented as opt-in — not part of the default.

## CLI flags

| Flag | Behavior |
|---|---|
| `--prompt` / `-p` | enable section |
| `--no-prompt` | disable section |
| default | enabled (no .env required) |

> **Conflict resolved:** `-p` was previously used by `--install-defaults`. That section is being renamed to `--install-packages` / `-i` in this same release (see top of file).

Add `"prompt"` to the `SECTIONS=(...)` array and the `run_section` dispatcher table.

## Test plan

1. Run on a fresh user account — verify `~/.bashrc` contains the guarded block
2. Run again — verify block is **not duplicated** (grep for the marker)
3. Set `PROMPT_PS1_TEMPLATE='[\u@\h \W]\$ '` and re-run — verify the block is **replaced**, not appended
4. Login as that user — verify prompt renders correctly
5. **cd into a brand-new git repo with zero commits** — verify branch appears (regression test for the `git branch` bug)
6. cd out — verify branch disappears

## Acceptance criteria

- `~/.bashrc` contains exactly one `>>> production-server-script:PROMPT >>>` block per user
- Re-running `setup.sh` with same config does not duplicate the block
- Editing `PROMPT_PS1_TEMPLATE` and re-running **replaces** the block in place
- Default PS1 works on fresh repos (no commits)
- Default PS1 works out-of-the-box without user config
- `.env.example` documents `PROMPT_ENABLED` and `PROMPT_PS1_TEMPLATE`
- No regression to existing sections
- `--install-packages` / `-i` rename is in CHANGELOG as a breaking change
