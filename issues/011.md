# Issue #011 — Pull and install luozongbao/server-report-script

**Severity**: feature
**Status**: open
**Target**: v1.1.0
**File**: [setup.sh](../../setup.sh) — new section

## Problem

The user maintains a companion repo at [`luozongbao/server-report-script`](https://github.com/luozongbao/server-report-script) which collects server diagnostics and reports them. Installing it manually is multi-step:

1. Open the [releases page](https://github.com/luozongbao/server-report-script/releases) in a browser
2. Download the `Source code (zip)` asset for the desired tag (e.g. `v.2.0.zip`)
3. Upload it to the server (scp / rsync / etc.)
4. Unzip it into `/opt/server-report-script/`
5. Run the upstream installer (or manually copy scripts to `/usr/local/bin`)
6. Configure a cron job or systemd timer for daily reports

`setup.sh` should automate this as an opt-in section.

## Proposed design

Add a new section `section_server_report` that, when enabled:
1. Reads `SERVER_REPORT_VERSION` from `.env` (literal tag, e.g. `v.2.0` — **with the dot after `v`**, matching the upstream release URL pattern)
2. Downloads the **release zip** directly from the GitHub archive URL — no `git clone`, no GitHub API calls (works even on networks that can't reach `api.github.com`)
3. Verifies the SHA256 checksum (if a `.sha256` file is published alongside the zip)
4. Extracts to `/opt/server-report-script/`
5. Runs the upstream installer if one exists (`install.sh` or `Makefile install`)
6. Symlinks the main binary to `/usr/local/bin/server-report`
7. Optionally installs a systemd timer if the upstream provides a `.service` + `.timer` unit

## .env variables

```bash
# GitHub owner/repo
SERVER_REPO="luozongbao/server-report-script"

# Version tag — literal tag matching the upstream release URL pattern.
# IMPORTANT: keep the dot after `v` (e.g. `v.2.0`) — the upstream archive
# URL is `archive/refs/tags/v.2.0.zip`, not `archive/refs/tags/v2.0.zip`.
SERVER_REPORT_VERSION=v.2.0

# Set to "true" to install + enable systemd timer for daily reports
SERVER_REPORT_TIMER=true
```

## CLI flags

| Flag | Behavior |
|---|---|
| `--server-report` / `-R` | enable section |
| `--no-server-report` | disable section |
| default | disabled (opt-in) |

Add `"server-report"` to `OPT_IN_SECTIONS=(...)`.

## Implementation sketch

```bash
section_server_report() {
  section "Install luozongbao/server-report-script"
  local repo="${ENV[SERVER_REPO]:-luozongbao/server-report-script}"
  local ver="${ENV[SERVER_REPORT_VERSION]:-v.2.0}"

  # Build the GitHub archive URL directly. No API call needed — the tag
  # is a literal value from .env (e.g. "v.2.0").
  local zip_url="https://github.com/${repo}/archive/refs/tags/${ver}.zip"
  local tmpdir; tmpdir=$(mktemp -d)
  local archive="$tmpdir/srs.zip"

  info "Downloading $repo @ $ver"
  if ! curl -fsSL -o "$archive" "$zip_url"; then
    err "Download failed: $zip_url"
    rm -rf "$tmpdir"; return 1
  fi

  # Optional checksum verify
  if curl -fsSL -o "$archive.sha256" "${zip_url}.sha256" 2>/dev/null; then
    if ! (cd "$tmpdir" && sha256sum -c srs.zip.sha256 >/dev/null 2>&1); then
      err "Checksum mismatch — refusing to install"
      rm -rf "$tmpdir"; return 1
    fi
    ok "Checksum verified"
  else
    warn "No .sha256 asset published — skipping checksum verification"
  fi

  # Extract (zip, not tarball)
  mkdir -p /opt/server-report-script
  unzip -q "$archive" -d "$tmpdir"
  # Zip extracts to server-report-script-<ver>/; flatten into /opt
  shopt -s dotglob
  cp -af "$tmpdir"/server-report-script-*/. /opt/server-report-script/
  shopt -u dotglob
  ok "Installed to /opt/server-report-script"

  # Run upstream installer if present
  if [[ -x /opt/server-report-script/install.sh ]]; then
    info "Running upstream installer"
    /opt/server-report-script/install.sh || warn "upstream install.sh exited non-zero"
  fi

  # Symlink main binary
  if [[ -x /opt/server-report-script/bin/server-report ]]; then
    ln -sf /opt/server-report-script/bin/server-report /usr/local/bin/server-report
    ok "Symlinked /usr/local/bin/server-report"
  fi

  # Optional systemd timer
  if [[ "${ENV[SERVER_REPORT_TIMER]:-}" =~ ^[Tt]rue$ ]]; then
    if [[ -f /opt/server-report-script/systemd/server-report.timer ]]; then
      cp /opt/server-report-script/systemd/server-report.{service,timer} /etc/systemd/system/
      systemctl daemon-reload
      systemctl enable --now server-report.timer
      ok "Enabled server-report.timer"
    else
      warn "No systemd unit shipped — skipping timer"
    fi
  fi

  rm -rf "$tmpdir"
}
```

> **Why zip, not tar.gz?** GitHub publishes both, but the zip URL is the canonical
> "Source code (zip)" download button on every release page, and matches what an
> admin would copy from the browser. Using zip also lets us skip the GitHub
> releases API entirely, so the section works on hosts that can reach
> `github.com` but **not** `api.github.com` (common in China-region networks).

## Test plan

1. Run with `SERVER_REPORT_VERSION=v.2.0` — verify download + extract + symlink
2. Re-run — verify idempotent (overwrites in place, no duplicate symlinks)
3. Run with bogus version (e.g. `v9.9.9`) — verify graceful error, no partial install
4. Run with `SERVER_REPORT_TIMER=true` — verify timer is active (`systemctl list-timers`)
5. **Network restriction test** — block `api.github.com` at the firewall but leave `github.com` reachable; verify the section still works (confirms we don't depend on the GitHub API)

## Acceptance criteria

- Downloads from the literal GitHub archive URL — **no GitHub API calls, no git clone**
- Optional checksum verification
- Idempotent re-installs
- Upstream `install.sh` invoked if present
- Optional systemd timer integration
- Works in `--non-interactive` mode when all `.env` keys set
- Works on networks where `api.github.com` is blocked but `github.com` is reachable
