# Issue #006 — CRLF in ssh_key.pub not stripped

**Severity**: low
**Status**: open
**Target**: v1.1
**File**: [setup.sh:546](../../setup.sh#L546)

## Problem

```bash
file_pubkey=$(awk '{$1=$1; print}' "$key_file")
```

`awk`'s `$1=$1` rebuilds the line with collapsed whitespace, but does **not** strip a trailing `\r`. If `ssh_key.pub` was:
- Saved on Windows
- Edited in an editor that adds CRLF (VS Code on Windows, Notepad++)
- Pulled from a git repo with `core.autocrlf=true`

Then the value ends up as:

```
ssh-ed25519 AAAA...== user@host\r
```

When written to `authorized_keys`, SSH reads it as a literal `\r` at end of line and **silently rejects the key**.

## Reproducer

```bash
printf "ssh-ed25519 AAAA== user@host\r\n" > /tmp/test_key.pub
awk '{$1=$1; print}' /tmp/test_key.pub | od -c | head
# Shows trailing \r still present
```

## Proposed fix

Pipe through `tr -d '\r'` after awk:

```bash
file_pubkey=$(awk '{$1=$1; print}' "$key_file" | tr -d '\r')
```

Same fix for the `SSH_PUBLIC_KEY` env value:

```bash
# In env_or_prompt or just before write
file_pubkey="${file_pubkey//$'\r'/}"
```

## Test plan

1. Save a CRLF key to `ssh_key.pub`
2. Run `sudo ./setup.sh --ssh-key` in non-interactive mode with `SSH_PUBLIC_KEY` unset
3. Verify `authorized_keys` has no `\r` (use `cat -A`)
4. Verify SSH login works (or at least `ssh-keygen -l -f ~/.ssh/authorized_keys` succeeds)
