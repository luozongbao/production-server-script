# Issue #005 — Dead FLAG_* variables

**Severity**: cosmetic
**Status**: open
**Target**: v1.1
**File**: [setup.sh:42-51, 107-128](../../setup.sh#L42-L51)

## Problem

10 `FLAG_*` variables are declared and assigned in the CLI parser but **never read anywhere**:

```bash
FLAG_TIMEZONE=""
FLAG_HOSTNAME=""
FLAG_FIREWALL=""
FLAG_SSH_KEY=""
FLAG_SWAP=""
FLAG_FAIL2BAN=""
FLAG_SSH_HARDEN=""
FLAG_APT_UPGRADE=""
FLAG_ADD_REPO=""
FLAG_INSTALL_DEFAULTS=""
```

The parser still assigns to them in every case branch (e.g. `FLAG_TIMEZONE=true`), but actual enable/disable logic uses `CLI_ENABLE_LIST` / `CLI_DISABLE_LIST`. Confirmed via grep — zero reads outside the parser itself.

## Why it's a bug

- Misleading — readers think `FLAG_HOSTNAME` matters, but it's purely vestigial
- Future maintainers may add `if [[ "$FLAG_FIREWALL" == "true" ]]` checks that don't actually work as intended (because `is_enabled()` only consults the LIST arrays)
- Dead code clutters the parser

## Proposed fix

Delete lines 42-51 and the `FLAG_*=...` assignments in the parser (lines 107-128). Keep only `CLI_FLAG_GIVEN`, `CLI_ENABLE_LIST`, `CLI_DISABLE_LIST`, `CLI_HOSTNAME_VALUE` (the actually-used state).

Estimated diff: -30 lines.

After fix: `bash -n setup.sh` + run each of the 32 CLI flag combinations and confirm Plan output lists the expected sections.
