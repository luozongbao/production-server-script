# Issue #010 — Configure Netplan (static IP / DHCP / WiFi)

**Severity**: feature
**Status**: open
**Target**: v1.1.0
**File**: [setup.sh](../../setup.sh) — new section

## Problem

Many bare-metal / VPS servers get DHCP by default, which is fine for cloud VMs but problematic for:
- On-prem servers that need a **static IP**
- WiFi-equipped boxes (single-board computers, laptops) that need **WPA2-PSK** config
- Servers where the gateway must be explicitly set

Netplan is the standard renderer on Ubuntu 18.04+ (and is present on Debian 11+ via `ifupdown` → netplan migration). Currently `setup.sh` does not touch networking at all.

## Proposed design

Add a new section `section_netplan` that, when enabled:
1. Reads `NETPLAN_CONFIG` from `.env` (multi-line YAML string), OR
2. Prompts the user interactively for: interface, method (`dhcp` / `static`), address, gateway, DNS, WiFi SSID/passphrase
3. Writes the config to `/etc/netplan/99-production-server-script.yaml` (high number → wins)
4. Runs `netplan generate` to validate
5. **Does NOT auto-apply** — prints `netplan try` and `netplan apply` as next-step commands

**Critical safety:** applying the wrong netplan config **bricks remote access**. The section must:
- Write to a versioned file (`99-production-server-script.yaml`)
- Run `netplan generate` (validates without applying)
- Print the diff vs the current active config
- Require an **explicit `--apply-netplan`** CLI flag to actually `netplan apply`
- In `--non-interactive` mode, refuse unless `NETPLAN_APPLY=true` is set

## .env variables

```bash
# Set to "true" to write netplan config (validate only by default)
NETPLAN_ENABLED=

# Interface name (e.g. eth0, enp0s3, wlan0)
NETPLAN_INTERFACE=

# "dhcp" or "static"
NETPLAN_METHOD=dhcp

# For static:
NETPLAN_ADDRESS=192.168.1.100/24
NETPLAN_GATEWAY=192.168.1.1
NETPLAN_DNS="1.1.1.1 8.8.8.8"

# For WiFi (static method only):
NETPLAN_WIFI_SSID=
NETPLAN_WIFI_PASSWORD=
```

## CLI flags

| Flag | Behavior |
|---|---|
| `--netplan` / `-N` | enable section |
| `--netplan-apply` | write config AND run `netplan apply` (DANGEROUS) |
| `--no-netplan` | disable section |
| default | disabled (opt-in — this is risky) |

Add `"netplan"` to `OPT_IN_SECTIONS=(...)` so it only runs when flag given or `NETPLAN_ENABLED=true`.

## Test plan

1. Run with bogus config — `netplan generate` should fail loudly, NOT apply
2. Run with valid DHCP config — file written, generate succeeds, no apply
3. Run with `--netplan-apply` and DHCP — config applied, network stays up
4. (Manual only) Run with `--netplan-apply` and broken static — verify `netplan try` would rollback in 120s

## Acceptance criteria

- Section is **opt-in** by default
- Without `--netplan-apply`, no network change takes effect
- `.env.example` documents every variable
- Re-running is idempotent (config file overwritten, not duplicated)
- A safety banner is printed before any `netplan apply`
