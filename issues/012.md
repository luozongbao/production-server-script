# Issue #012 — Configure msmtp and write .msmtprc

**Severity**: feature
**Status**: open
**Target**: v1.1.0
**File**: [setup.sh](../../setup.sh) — new section, depends on apt-installed `msmtp`

## Problem

`msmtp` is a popular lightweight SMTP client that many servers use to send mail (cron job output, monitoring alerts, etc.) without running a full MTA like Postfix. Installing `msmtp` from apt gives you the binary, but **does not** write `~/.msmtprc` — which contains the SMTP server, credentials, and TLS settings.

Admins who install `msmtp` expect `~/.msmtprc` to be created as part of the setup, but right now `setup.sh` doesn't touch it at all. Result: cron jobs fail silently, "mail" goes nowhere.

## Design (revised — simplified)

### Trigger model

`msmtp` is **not** an opt-in section. It runs in **two** scenarios:

| Invocation | `msmtp` runs? |
|---|---|
| `sudo ./setup.sh --msmtp` / `-m` (selective enable) | yes |
| `sudo ./setup.sh` (RUN ALL — no flags) | yes — section runs alongside everything else |
| `sudo ./setup.sh --no-msmtp` | no |
| `sudo ./setup.sh --msmtp` with `MSMTP_HOST` (or other required key) blank in `.env` | **no** — section exits non-zero with a clear "set these keys" message |

Remove `msmtp` from `OPT_IN_SECTIONS=(...)`. There is no `MSMTP_ENABLED` variable — presence of `--msmtp` (or RUN ALL) is the only gate.

### `.env` variables (final, minimal)

```bash
# SMTP server settings. ALL FOUR are required for the section to proceed;
# if any is blank (and we're running), exit with a clear message instead of
# silently writing an incomplete .msmtprc.
MSMTP_HOST=smtp.example.com
MSMTP_PORT=587
MSMTP_USER=alerts@example.com
MSMTP_FROM=alerts@example.com

# Optional: send a smoke test to this address every time the section runs.
# Leave blank to skip the test entirely. Must match ^[^@[:space:]]+@[^@[:space:]]+$.
MSMTP_TEST_EMAIL_TO=
```

**Removed variables** (previously considered, dropped for simplicity):
- `MSMTP_ENABLED` — flag is the gate, no double-bookkeeping
- `MSMTP_PASSWORD` — never, ever stored in `.env`
- `MSMTP_PASSWORD_FILE` — there is no `--non-interactive` mode for msmtp in this revision; the password is **always** prompted interactively and re-typed for confirmation. (We can revisit if/when there's a real cloud-init use case.)

### Password handling

The password is **always** collected by interactive `read -s`, then re-typed for confirmation. Mismatch → re-prompt loop. The password lives only in a local Bash variable that is `unset` via `trap ... RETURN` as soon as `~/.msmtprc` is written.

If `sudo ./setup.sh` is ever run non-interactively and the msmtp section is reached, the section fails fast with `msmtp requires interactive input (password); rerun without --non-interactive`. (We are NOT supporting unattended msmtp setup in this revision.)

### What gets written to disk

Only one file is ever written:
- `/home/$TARGET_USER/.msmtprc` — mode `0600`, owner `$TARGET_USER`, written via `install -m 0600 -o $TARGET_USER -g $TARGET_USER`. No sentinel, no companion files — keeps the design minimal.

### Existing `.msmtprc` handling

When `/home/$TARGET_USER/.msmtprc` already exists at run start, we offer the user a binary choice. **Merge is intentionally not an option** — deciding which lines to keep vs. discard from a config file is confusing and bug-prone (what if the user has a custom `logfile`, custom TLS settings, an alias domain in `domain`, etc.?). Overwrite or abort is unambiguous.

| User choice | Default? | Result |
|---|---|---|
| `o` (overwrite) | YES — Enter on empty input | Backup existing → `.msmtprc.bak.YYYYMMDD-HHMMSS`, then write a fresh managed config |
| `a` (abort) | | Section exits cleanly, prints `existing .msmtprc preserved` |

Defaulting to `o` is deliberate: most users re-running `--msmtp` want the new values applied. Users who want to keep their hand-tuned file pick `a`.

**Non-interactive runs**: if an existing `.msmtprc` is detected and no choice can be collected, **abort** and exit non-zero — never silently overwrite.

### Test email (smoke test)

After writing `.msmtprc`, if `MSMTP_TEST_EMAIL_TO` is set and matches the email regex, send a test message via `msmtp`. The test runs **every time** the section runs — there is no "once only" mechanism. If you don't want the test on a particular run, leave `MSMTP_TEST_EMAIL_TO` blank in `.env`. (Bonus: re-running the test is the fastest way to confirm credentials still work after a server move.)

## CLI flags

| Flag | Behavior |
|---|---|
| `--msmtp` / `-m` | enable section (selective run) |
| `--no-msmtp` | disable section (selective run or RUN ALL) |
| default | enabled — runs in RUN ALL |

**Removed from `OPT_IN_SECTIONS`**: `msmtp`. (No `required_keys_for_section` rule will trigger auto-enable either.)

## Implementation sketch (revised)

```bash
section_msmtp() {
  section "msmtp SMTP client configuration"

  # Step 1: install if missing (target_user's mta, not just for root)
  if ! command -v msmtp >/dev/null 2>&1; then
    info "msmtp not installed — installing via apt"
    if ! apt-get install -y -qq msmtp msmtp-mta; then
      err "apt-get install msmtp failed — check apt output above"
      return 1
    fi
    ok "msmtp installed"
  fi

  # Step 2: read SMTP settings from .env. ALL required keys must be set.
  local host="${ENV[MSMTP_HOST]:-}"
  local port="${ENV[MSMTP_PORT]:-587}"
  local user="${ENV[MSMTP_USER]:-}"
  local from="${ENV[MSMTP_FROM]:-$user}"
  local missing=()
  [[ -z "$host" ]] && missing+=(MSMTP_HOST)
  [[ -z "$user" ]] && missing+=(MSMTP_USER)
  if (( ${#missing[@]} > 0 )); then
    err "missing required .env keys: ${missing[*]}"
    err "set them in .env and re-run, or pass --no-msmtp to skip this section"
    return 1
  fi
  port="${port:-587}"
  [[ -z "$from" ]] && from="$user"

  # Step 3: collect the SMTP password interactively (always — see Password handling)
  if [[ ! -t 0 ]]; then
    err "msmtp requires interactive input (password); rerun from a TTY"
    return 1
  fi
  local pass
  while :; do
    local pass1 pass2
    read -r -s -p "  SMTP password: " pass1; echo
    [[ -z "$pass1" ]] && { warn "password cannot be empty"; continue; }
    read -r -s -p "  Confirm password: " pass2; echo
    [[ "$pass1" != "$pass2" ]] && { warn "passwords do not match — try again"; continue; }
    pass="$pass1"; unset pass1 pass2; break
  done
  trap 'unset pass' RETURN

  # Step 4: existing .msmtprc → overwrite (default) / abort
  local rcfile="$TARGET_HOME/.msmtprc"
  if [[ -f "$rcfile" ]]; then
    if [[ ! -t 0 ]]; then
      err "existing .msmtprc detected and no TTY — aborting to avoid clobber"
      return 1
    fi
    local ans="o"
    read -r -p "  $rcfile already exists. [o]verwrite / [a]bort [o]: " ans
    case "$ans" in
      a|A) info "aborted; existing $rcfile preserved"; return 0 ;;
      *)   cp -a "$rcfile" "${rcfile}.bak.$(date +%Y%m%d-%H%M%S)" ;;
    esac
  fi

  # Step 5: write /home/$TARGET_USER/.msmtprc — full overwrite, mode 0600
  install -m 0600 -o "$TARGET_USER" -g "$TARGET_USER" \
    /dev/null "$rcfile"  # create or truncate, mode 0600, owner TARGET_USER

  cat > "$rcfile" <<EOF
# Managed by production-server-script (msmtp)
defaults
auth           on
tls            on
tls_starttls   on
logfile        ~/.msmtp.log

account        default
host           $host
port           $port
from           $from
user           $user
password       $pass
EOF
  chown "$TARGET_USER":"$TARGET_USER" "$rcfile"
  chmod 600 "$rcfile"
  ok "Wrote $rcfile (mode 600, owner $TARGET_USER)"

  # Step 6: optional smoke test (runs every time MSMTP_TEST_EMAIL_TO is set)
  if [[ -n "${ENV[MSMTP_TEST_EMAIL_TO]:-}" \
        && "${ENV[MSMTP_TEST_EMAIL_TO]}" =~ ^[^@[:space:]]+@[^@[:space:]]+$ ]]; then
    local body="From: $from\nTo: ${ENV[MSMTP_TEST_EMAIL_TO]}\nSubject: setup.sh msmtp test\n\nTest from $(hostname) at $(date)."
    if printf '%b' "$body" | msmtp "${ENV[MSMTP_TEST_EMAIL_TO]}" >/dev/null 2>&1; then
      ok "Sent test email to ${ENV[MSMTP_TEST_EMAIL_TO]}"
    else
      warn "Test email send failed — check $rcfile and ~/.msmtp.log"
    fi
  fi
}
```

## Test plan

1. Run `sudo ./setup.sh` (RUN ALL, no flags) without msmtp installed, with `MSMTP_HOST/PORT/USER/FROM` set in `.env` — apt installs `msmtp` + `msmtp-mta`, prompts for password twice, writes `/home/$TARGET_USER/.msmtprc` mode `0600`, owner `$TARGET_USER`. **No** `.msmtprc.configured` sentinel is created.
2. Run `sudo ./setup.sh --msmtp` on a system with msmtp pre-installed — section runs without re-installing. Warns "already installed", prompts for password, writes `.msmtprc`.
3. Run `sudo ./setup.sh --msmtp` with `MSMTP_HOST` blank in `.env` — section exits non-zero with `missing required .env keys: MSMTP_HOST` and instructions; **no** interactive prompt for the missing key.
4. Run `sudo ./setup.sh --msmtp` with `MSMTP_USER` set but `MSMTP_FROM` blank — `MSMTP_FROM` defaults to `MSMTP_USER` (no prompt, no error).
5. Interactive password flow: type `<pw1>`, confirm `<pw2>` where `<pw1> != <pw2>` — warn `passwords do not match — try again`, loop again. Then type matching pair — file written with matching password bytes (`xxd` round-trip check).
6. Interactive password flow: press Enter (empty) on first prompt — warn `password cannot be empty`, loop again.
7. Re-run interactively with an existing `/home/$TARGET_USER/.msmtprc`: prompt says `[o]verwrite / [a]bort [o]:`. Press Enter — existing file is backed up to `.msmtprc.bak.YYYYMMDD-HHMMSS` and a fresh managed file is written.
8. Re-run non-interactively with an existing `.msmtprc`: section fails fast with `existing .msmtprc detected and no TTY — aborting to avoid clobber` (no silent overwrite).
9. After running interactively: confirm `pass` is `unset` in the script's scope (the `trap 'unset pass' RETURN` cleanup). `set | grep '^pass='` returns nothing after the section exits.
10. Run `sudo ./setup.sh --msmtp` with `MSMTP_TEST_EMAIL_TO=you@example.com` — test email is sent; on failure, see `~/.msmtp.log`. Leave `MSMTP_TEST_EMAIL_TO` blank — no test is sent. Re-run (test configured, file now exists) — test is sent **again** (no once-only sentinel).

## Acceptance criteria

- `msmtp` is part of RUN ALL — it runs on `sudo ./setup.sh` with no flags, and on `--msmtp/-m`; it does **not** run on `--no-msmtp`. `msmtp` is removed from `OPT_IN_SECTIONS`.
- `.msmtprc` is written to `/home/$TARGET_USER/.msmtprc` with **0600** perms, owner `$TARGET_USER` (msmtp refuses to run with looser perms).
- **No `MSMTP_ENABLED`, `MSMTP_PASSWORD`, `MSMTP_PASSWORD_FILE`, or `MSMTP_ROOT_CONFIG` keys exist in `.env`** — the only `.env` keys for this feature are `MSMTP_HOST`, `MSMTP_PORT`, `MSMTP_USER`, `MSMTP_FROM`, `MSMTP_TEST_EMAIL_TO`.
- Missing required `.env` keys (`MSMTP_HOST` or `MSMTP_USER`) cause the section to exit non-zero with a clear "set these keys" message — no interactive prompts for the missing values.
- Interactive password prompt uses `read -s` (no echo), confirms with a second `read -s` prompt; mismatches and empty input re-prompt; the local variable is `unset` via `trap ... RETURN` after `.msmtprc` is written.
- If `sudo ./setup.sh` is non-interactive and msmtp section is reached, the section fails fast with a clear message rather than silently producing a broken config.
- Existing `.msmtprc` → interactive binary choice `[o]verwrite (default) / [a]bort`. Non-interactive + existing file → abort with non-zero exit. **No merge option.** A timestamped `.msmtprc.bak.YYYYMMDD-HHMMSS` is created before overwriting.
- `MSMTP_TEST_EMAIL_TO` triggers a test send **every time** the section runs; there is no once-only sentinel. Leaving it blank disables the test. The test result is reported (`ok` or `warn`).
- `MSMTP_FROM` defaults to `MSMTP_USER` when blank.
- Idempotent: re-running `--msmtp` produces a working `.msmtprc` with the current `.env` values (default = overwrite).
