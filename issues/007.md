# Issue #007 — Misleading Summary "apt: N packages" count

**Severity**: cosmetic
**Status**: open
**Target**: v1.1
**File**: [setup.sh:952](../../setup.sh#L952)

## Problem

```bash
if is_enabled apt-upgrade; then
  pkg_count=$(dpkg -l 2>/dev/null | wc -l)
  ok "apt:          $pkg_count packages installed"
fi
```

`dpkg -l | wc -l` returns the count of **all** packages on the system, not "packages upgraded by this script". The label is misleading.

Example: server has 2000 packages pre-installed. After running `apt-upgrade`, the count might be 2010 (10 upgraded + some new deps). The Summary shows "2010 packages installed" which sounds like the script installed 2010 packages.

## Proposed fix

Either remove the line, or relabel:

```bash
if is_enabled apt-upgrade; then
  pkg_count=$(dpkg -l 2>/dev/null | wc -l)
  ok "apt:          $pkg_count packages on system"
fi
```

Or just drop the line entirely — the apt section already prints its own completion message.

## Test plan

1. Run `--apt-upgrade` on a clean system
2. Check Summary output reads naturally
